# Public API stability

OpenKline's public package boundary is the root `openkline` ESM/type export and
the separate `@openkline/react` binding. `src/` implementation modules are not
consumer contracts unless they are re-exported from those package entries.
The Next.js Studio and Vanilla examples are consumers, not package internals.

The machine-readable export surface is generated by
`node scripts/public-api-inventory.mjs` into
[`docs/audits/public-api-inventory.json`](../audits/public-api-inventory.json).
The starting compatibility baseline is
[`docs/audits/public-api-baseline.json`](../audits/public-api-baseline.json).

`node scripts/api-compatibility.mjs` compares runtime/type export names and
normalized declaration signatures. Removed exports and changed exported
signatures fail the gate; additive exports are reported separately. Formatting
changes that do not alter the normalized declaration are not treated as
breaking. Worker protocols and serialized documents are versioned contracts and
are covered by their existing protocol/round-trip tests rather than inferred
from declaration text alone.

When a strict hash changes, `npm run api:diagnostics` compares the historical
source declarations with the current TypeScript AST. It reports additive
public class methods, optional interface fields, new root exports, removals,
changed signatures, required-property additions, and overload changes. This is
an explanation and review aid, not a relaxed compatibility policy: the
historical baseline remains unchanged until the owner approves the exact
before/after contract.

No breaking API change was introduced in Phase 8.5. Any future incompatible
change requires an owner decision, a documented before/after contract, and
migration guidance before implementation. No new versioning policy is inferred
by this document.

Phase 10 adds multi-timeframe calculation functions, chart-owned indicator and
reference APIs, optional workspace fields, and an optional Canvas2D dash field
for overlay lines. These are additive declarations; the historical baseline is
not rewritten automatically. Run `npm run api:diagnostics` and review the
reported additive delta before any owner-approved baseline update. Version-1
workspaces without `multiTimeframe` remain valid.
